# Урок 02 — Екрани, които се променят

**Преди да четете, седем думи.** По един ред за всяка; останалите от поредицата идват в урока, където се използват.

- **Състояние:** данна, която екранът помни и която може да се променя. Срещнахте я в урок 01; тук тя е темата.
- **Рекомпозиция:** когато Compose изпълнява отново вашите функции, за да обнови екрана, защото някоя данна се е
  променила.
- **Събитие:** нещо, което се случва и за което приложението научава, като докосване на бутон.
- **Издигане на състоянието:** изваждане на състоянието от един екран и пазенето му във функцията, която го вика.
- **Интерфейс:** списък с това, което може да се поиска от нещо, без да се казва как то го изпълнява.
- **Имплементация:** клас, който наистина изпълнява онова, което интерфейсът иска. Може да има няколко.
- **Тестов дубльор:** имплементация, направена само за тестовете, която отговаря онова, от което тестът има нужда.

**Какво отнасяте:** приложение с три екрана —приветствие, вход и начален екран— което минава от единия към другия, и
умение да кажете защо екранът се е променил всеки път: коя стойност се е променила, кой я е променил и кой я е
прочел.

**Новата идея на този урок (единствената, която се оценява):** състоянието. Когато се промени стойност на състояние,
която екранът е прочел, Compose **планира рекомпозиция**, за да обнови каквото е нужно, и екранът се чертае отново.
Преминаването от един екран към друг е точно това: стойност, която се променя. Освен това упражнявате една
спомагателна практика, която също се проверява: отделянето на решението дали някой влиза в договор (интерфейс), с
имплементация само за тестовете (стъпка 3).

**Бележка за текстовете на приложението.** Проектът на курса носи екранните си текстове на испански, а файловете в
`lecciones/` не са преведени: автоматичните проверки на курса (`verifica`) търсят именно тези текстове. Затова в
блоковете с код, в изходите от терминала и в скиците на екрана текстовете остават така, както ги има проектът, а в
прозата урокът ги дава на български и първия път слага оригинала в скоби: екраните „Влезте във вашия акаунт“ („Entra
a tu cuenta“), „Здравейте, Ана“ („Hola, Ana“) и „Тук ще виждате поръчките си“ („Aquí verás tus órdenes“), бутонът
„Продължете“ („Continuar“) и съобщението „Все още не можете да влезете“ („Todavía no se puede entrar“). Тези от урок 01
са същите: „Магазинът“ („La tienda“), „Влезте“ („Entrar“) и „Здравейте!“ („¡Hola!“).

## Сцената

Трите екрана работят. Преди да затворите, преглеждате файла, за да го оставите чист, и една дума ви пречи: `remember`.
Редът се чете същото и без нея. Изтривате я.

Компилира се. Отваряте приложението: приветствието изглежда същото. Докосвате „Влезте“.

Нищо не се случва. Няма съобщение за грешка. Приветствието си стои. Докосвате отново. Нищо.

Тази промяна съществува и е измерена: тя е „Счупете едно нарочно“ от стъпка 4. Само с тази изтрита дума симулираните

## Стъпка 1 · Предвидете какво прави една стойност на състояние

Тази стъпка е ваша, без Claude Code. Отворете `app/src/main/java/mx/habil/ejemplo/tienda/Bienvenida.kt`. Това е екранът
от урок 01, с тези три части:

```kotlin
    var saludando by remember { mutableStateOf(false) }      // състоянието
    …
        Button(onClick = { saludando = true }) {             // събитието го променя
            Text("Entrar")
        }
        if (saludando) {                                     // екранът го чете
            Text("¡Hola!")
        }
```

**Първо предвидете.** Сменете `saludando = true` с `saludando = !saludando` (`!` обръща: от `false` на `true` и
обратно). Напишете в `respuestas/02.md`, преди да изпълните каквото и да е: какво се вижда след първото докосване,
след второто и след третото?

**Сега го проверете.** С отворен емулатор или с включен телефон:

```bash
./gradlew installDebug      # компилира и инсталира; не отваря приложението
```

Отворете приложението, докоснете три пъти и сравнете. Ако предвиждането ви не е излязло вярно, не го изтривайте:
запишете отдолу кой ред би ви дал отговора.

**Какво се случи, по ред.** Това е веригата на целия урок:

1. Докосвате бутона: това е **събитието**.
2. `onClick` променя стойността. Нищо не чертае.
3. Compose следи тази стойност, защото тя е родена от `mutableStateOf`. Когато се промени, **планира рекомпозиция**:
   да изпълни отново онова, което я е прочело и има нужда от обновяване.
4. В този пример вашата функция се изпълнява пак. `remember` ѝ връща запазената стойност, не нова.
5. `if` чете сегашната стойност и описанието на екрана излиза различно.

Не пишете код, като предполагате колко пъти или в какъв ред ще се изпълни една функция `@Composable`: според
документацията Compose може да прескача онези, които не са се променили, и да изпълнява други много пъти.

Никой не „добавя“, нито „маха“ поздрава: функцията описва екрана за стойността от този момент.

Преди да продължите, върнете на ръка реда на бутона на `Button(onClick = { saludando = true })`. Така запазвате
всяка друга промяна, която може да сте направили. За да се уверите, че файлът е останал какъвто е бил, тази команда не
бива да показва нищо (само гледа, не променя файла ви):

```bash
git diff -- app/src/main/java/mx/habil/ejemplo/tienda/Bienvenida.kt
```

**Доказва се с:** вашето написано предвиждане, сравнено с изпълнението (цел 2.1).

## Стъпка 2 · На ръка: една стойност решава кой екран се вижда

Също без Claude Code. Ще напишете два екрана и функцията, която избира кой от тях се чертае.

**Първо предвидете.** Ако „на кой екран съм“ е стойност на състояние, в коя функция трябва да живее: в `Bienvenida`,
в екрана за вход или в трета, която вика двете? Напишете коя и защо.

**1. Приветствието спира да пази състояние и подава сигнал.** В `Bienvenida.kt` изтрийте реда със `saludando`, блока
`if (saludando) { … }` и четирите `import` от `androidx.compose.runtime`, които не са `Composable`. Променете два реда:

```kotlin
fun Bienvenida(alEntrar: () -> Unit) {
    …
        Button(onClick = alEntrar) {
```

`alEntrar: () -> Unit` е параметър, чиято стойност е функция: не получава нищо (`()`) и не връща данна (`Unit`).
Екранът я изпълнява при докосване на бутона и не знае какво се случва после.

**2. Екранът за вход.** Създайте `PantallaEntrada.kt` в същата папка. Започва с `package
mx.habil.ejemplo.tienda` и със същите `import` като `Bienvenida.kt`:

```kotlin
@Composable
fun PantallaEntrada(rechazada: Boolean, alContinuar: () -> Unit) {
    Column(
        modifier = Modifier.fillMaxSize().padding(24.dp),
        verticalArrangement = Arrangement.Center,
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        Text("Entra a tu cuenta", style = MaterialTheme.typography.headlineLarge)
        Button(onClick = alContinuar) {
            Text("Continuar")
        }
        if (rechazada) {
            Text("Todavía no se puede entrar")
        }
    }
}
```

Не пази нищо и той: получава една данна (`rechazada`) и подава сигнал за докосване (`alContinuar`).

**3. Функцията, която пази състоянието.** Създайте `Tienda.kt`:

```kotlin
package mx.habil.ejemplo.tienda

import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

enum class Pantalla { BIENVENIDA, ENTRADA, INICIO }

@Composable
fun Tienda() {
    var pantalla by remember { mutableStateOf(Pantalla.BIENVENIDA) }

    when (pantalla) {
        Pantalla.BIENVENIDA -> Bienvenida(alEntrar = { pantalla = Pantalla.ENTRADA })
        Pantalla.ENTRADA -> PantallaEntrada(rechazada = false, alContinuar = { })
        Pantalla.INICIO -> Text("Aquí va el inicio")
    }
}
```

- **`enum class Pantalla { … }`** е затворен списък: една `Pantalla` може да бъде само едно от тези три.
- **`when (pantalla) { … }`** изпълнява клона за тази стойност. Ако ви липсва един от трите, не се компилира.
- **`alEntrar = { pantalla = Pantalla.ENTRADA }`** е функцията, която подавате на приветствието. То подава сигнал;
  тук се променя състоянието.

**4. Приложението да стартира в `Tienda`.** В `MainActivity.kt` редът със `setContent` става
`setContent { Tienda() }`.

**Проверете го в приложението.** `./gradlew installDebug`, отворете го и докоснете „Влезте“: трябва да остане екранът
„Влезте във вашия акаунт“ („Entra a tu cuenta“), а приветствието вече не бива да се вижда. „Продължете“ още не прави
нищо.
С готовото решение, в емулатора от изпитването (Pixel 9, Android 37, 18 ноември 2026 г.) се видя това: приветствието
с „La tienda“, „Tus órdenes, en tu bolsillo“ и „Entrar“; при докосване на „Entrar“ — „Entra a tu cuenta“ и
„Continuar“; а при докосване на „Continuar“ — съобщението „Todavía no se puede entrar“. Началният екран не се
появява в инсталираното приложение: до него стигат само тестовете.

**Какво току-що направихте.** Състоянието не остана в никой екран: вие го издигнахте до функцията, която ги вика. Това
е **издигане на състоянието** и документацията на Android го препоръчва: състоянието живее в най-близкия общ
предшественик на онези, които го четат, и на онези, които го променят; надолу пътуват данни, нагоре пътуват събития.

**`verifica` още не може да изпълни тестовете.** От корена на хранилището:

```bash

```

Това червено е очакваното **само** когато завършите стъпка 2, и то само защото още липсват `Entrada`, `EntradaFalsa` и
параметърът `entrada` на `Tienda`. **Вървите добре**, ако между редовете виждате тези (измерено на 18 ноември 2026 г.;
тези на Gradle се повтарят по няколко пъти):

```text

✅ Texto: en src/main hay un «fun Tienda(»
❌ No encontré «class EntradaFalsa» en src/test: la escribes tú en EntradaFalsa.kt (paso 3)
ℹ️  Estado guiado del paso 2: arriba faltan piezas del paso 3, y mientras falten las pruebas no compilan.
```

*(Това е изходът на `verifica`, точно както го отпечатва скриптът, на испански. На български казва: „Не намерих
«interface Entrada» в src/main: без него тестовете не се компилират (стъпка 3)“; „Текст: в src/main има «fun

започнали стъпка 3, това не е това червено: това е грешка, която трябва да поправите, преди да продължите. Например,

**Доказва се с:** в инсталираното приложение „Влезте“ ви води до екрана за вход (първата половина на цел 2.2).

## Стъпка 3 · С Claude Code: кой решава дали влизате

Липсва началният екран и липсва да се реши кой може да стигне до него. Днес няма доставчик (Google идва в урок 04) и
въпреки това тестовете трябва да минат през трите екрана.

Затова това решение не се пише вътре в никой екран. Декларира се отделно, като **интерфейс**: „от това може да се
поиска да влезе и то отговаря с името на онзи, който е влязъл, или с нищо“. И се пишат две **имплементации**:

| Имплементация | Къде живее | Какво отговаря | Кой я използва |
|---|---|---|---|
| `EntradaSinProveedor` | `app/src/main` (приложението) | Винаги „не“: `null` | Инсталираното приложение |
| `EntradaFalsa` | `app/src/test` (тестовете) | Винаги „да“, с името, което ѝ зададете | Само тестовете |

`EntradaFalsa` е **тестов дубльор**. За да не пусне истинското приложение никого без доставчик, спазваме това
правило: **приложението не носи никакъв начин за влизане без доставчик.** Според документацията на Android дубльор,
който живее в тестовия код, не пътува с приложението.

Тук влиза инструментът и винаги влиза по един и същи начин: **предвиждате → искате → четете какво е генерирал →
изпълнявате `verifica` → обяснявате със свои думи.**

1. **Предвидете.** Напишете в `respuestas/02.md`: от файловете `Bienvenida.kt`, `PantallaEntrada.kt`, `Tienda.kt` и
   `MainActivity.kt` кои ще се променят и кои не?
2. **Поискайте** от Claude Code, стоейки в `inicio/`: „Създай `Entrada.kt` с интерфейс `Entrada`, който има
   `fun entrar(): String?`, и клас `EntradaSinProveedor`, който връща `null`. Създай `Inicio.kt` с композируема функция
   `Inicio(nombre: String)`, която показва "Hola, ", последвано от името, и отдолу "Aquí verás tus órdenes". Направи
   `Tienda` да получава `entrada: Entrada`: при докосване на "Continuar" вика `entrada.entrar()`; ако върне име,
   минава към началния екран с това име; ако върне `null`, остава и слага `rechazada` на `true`. В `MainActivity`
   използвай `EntradaSinProveedor()`. В `app/src/test`, до `RecorridoTest.kt`, създай `EntradaFalsa.kt`: получава
   име, винаги го връща и отчита във `veces` колко пъти са я помолили да влезе. Не променяй `RecorridoTest.kt`, нито
   двата екрана, които вече съществуват.“
3. **Прочетете** цялата промяна, преди да я приемете. Тялото на функциите може да варира. Онова, което тестовете
   викат по име, е част от договора на този урок и трябва да остане такова, каквото е: `Entrada` с
   `fun entrar(): String?`, `EntradaSinProveedor()`, `Tienda(entrada = …)`, `EntradaFalsa(nombre)` с брояча си `veces`
   и текстовете на екраните. С други имена вашият дизайн може да е също толкова добър, но тези тестове няма да се
   компилират. Трябва да носи тези четири части:


```kotlin
// Tienda.kt — получава входа и пази три стойности на състояние
@Composable
fun Tienda(entrada: Entrada) {
    var pantalla by remember { mutableStateOf(Pantalla.BIENVENIDA) }
    var nombre by remember { mutableStateOf<String?>(null) }
    var rechazada by remember { mutableStateOf(false) }

    when (pantalla) {
        Pantalla.BIENVENIDA -> Bienvenida(alEntrar = { pantalla = Pantalla.ENTRADA })
        Pantalla.ENTRADA -> PantallaEntrada(
            rechazada = rechazada,
            alContinuar = {
                val quien = entrada.entrar()
                if (quien != null) {
                    nombre = quien
                    pantalla = Pantalla.INICIO
                } else {
                    rechazada = true
                }
            }
        )
        Pantalla.INICIO -> Inicio(nombre = nombre ?: "")
    }
}
```

|---|---|---|
| `No value passed for parameter 'alEntrar'` | Някой вика `Bienvenida()` без функцията | Подайте ѝ я: `Bienvenida(alEntrar = { … })` |
